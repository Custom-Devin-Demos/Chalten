# Intentional behaviour differences: Smalltalk Chalten vs Java port

Every deviation of the Java port from the Smalltalk implementation is listed here with the Smalltalk behaviour, the Java behaviour, the reason and the JUnit test that pins the Java side. Anything not listed is meant to behave identically; a difference found elsewhere is a bug.

Parity is enforced two ways (see `PLAN.md` §6 and §8):

- `./gradlew check` runs `checkTestParity`, which parses every SUnit class in `source/**/*Test*.st` and fails unless each selector has a same-named, enabled JUnit method in the same-named Java test class (report: `build/reports/test-parity/test-parity.md`). Classes listed in `test-parity-pending.txt` (U4) are reported, not failed.
- jqwik properties check the §6 invariants against `java.time`: `GregorianCalendarPropertiesTest`, `TimeOffsetPropertiesTest`, `DurationPropertiesTest` (`chalten-core`) and `MeasurePropertiesTest` (`chalten-measure`), with the generators of `org.chalten.testkit.ChaltenArbitraries`.

## `chalten-measure` (U3)

| # | Area | Smalltalk | Java | Reason | Test |
| --- | --- | --- | --- | --- | --- |
| M1 | Float amounts | `1.5 * day` holds a `Float`; `1.0 * day` is not an integer, so it prints `1.0 d` and formats as `P1.0D`. | There are no floating-point amounts: decimals are read exactly (`Fraction.parse("1.5")` is `3/2`, `"1.0"` is `1`). `1.0 * day` is `1 d` and formats as `P1D`. | Arithmetic must be exact. Formatting non-integer amounts still goes through `asFloat` printing, so every expected string of `ISO8601DurationFormatterTest` is unchanged. | `FractionTest.parsesIntegersFractionsAndDecimalsExactly`, `ISO8601DurationFormatterExtensionsTest.formatsNonDecimalFractionsAsSmalltalkPrintsTheirFloat` |
| M2 | `printString` of fractional quantities | A `Float` amount prints as a float (`1.5 h`); a `Fraction` amount prints as `(3/2) h`. | Every non-integer amount is a `Fraction` and prints as `(3/2) h`. | Consequence of M1. Integer amounts print identically (`365 d`, `12 mo`). | `TimeQuantityTest.printsLikeSmalltalk`, `FractionTest.printsLikeSmalltalk` |
| M3 | Quantity × quantity, quantity ÷ incommensurable quantity | Aconcagua builds derived units (`d·mo`, `d/mo`). | Not supported: `TimeQuantity` has no quantity product, and `dividedBy(TimeQuantity)` of incommensurable quantities throws `ArithmeticException("Cannot convert incommensurable units")`. Commensurable division returns the exact `Fraction` ratio, as in Aconcagua. | Chalten never uses derived time units. | `TimeQuantityTest.dividesCommensurableQuantitiesIntoRatios`, `TimeQuantityTest.cannotMixIncommensurableQuantities` |
| M4 | Incommensurable sums | Aconcagua v11 raises `ArithmeticError` (`Cannot add incommensurable quantities`); the parser returns several periods as a collection. | `TimeQuantity.plus` raises the same `ArithmeticException`; several periods are kept in `CompoundTimeQuantity` (ordered `parts()`, merged `totals()`, equality by totals). Its `toString()` is `3 yr + 5 mo + 4 d`. | `CompoundTimeQuantity` is the typed Java replacement for the collection of periods (and the old `MeasureBag`); its printing is Java-only. | `TimeQuantityTest.cannotMixIncommensurableQuantities`, `CompoundTimeQuantityTest.equalityFollowsTheTotals`, `DurationPropertiesTest.severalPeriodsRoundTripThroughISO8601` |
| M5 | Interval indices | `DiscreteInterval at:` is one-based and raises `SubscriptOutOfBounds` (`Index out of range`). | `DiscreteInterval` is a `java.util.List`: `get(i)` is zero-based (`get(0)` is `at: 1`) and throws `IndexOutOfBoundsException("Index out of range")`. `indexOf` returns `-1` instead of evaluating an `ifAbsent:` block. | Java collection conventions. | `DiscreteIntervalTest.indexesFromZero`, `DiscreteIntervalTest.findsOnlyActualElements` |
| M6 | Interval size limit | Unbounded (`count` is a `LargePositiveInteger` if needed). | Creation throws `ArithmeticException("Interval too large: n elements")` above `Integer.MAX_VALUE` elements. | `List.size()` is an `int`. | `DiscreteIntervalTest.rejectsTooLargeIntervals` |
| M7 | Interval steps | `DiscreteInterval` accepts any arithmetic objects (numbers, quantities). | Steps are `TimeQuantity`s and bounds implement `Steppable<T>` (`TimeQuantity`, dates, years). | Chalten only builds intervals of dates, years and quantities. | `DiscreteIntervalTest.cannotBeCreatedWithIncommensurableSteps`, `DiscreteIntervalTest.stepsOverQuantities`, `DurationPropertiesTest.dateIntervalsMatchSteppingWithPlus` |
| M8 | Unit lookup errors | `TimeUnits units >> #fortnight` raises `KeyNotFound`. | `TimeUnits.named("fortnight")` throws `IllegalArgumentException("key fortnight not found")`; `TimeUnits.find` returns an `Optional`. | Java exception idiom. | `TimeUnitTest.looksUpUnitsByName` |
| M9 | Localized messages | Error messages are `localized` through the image's current locale. | Messages are the English source strings. | `chalten-measure` has no localization; translated messages are U4's localization scope. | `TimeQuantityTest.cannotMixIncommensurableQuantities` |

## `chalten-core` (U2)

| # | Area | Smalltalk | Java | Reason | Test |
| --- | --- | --- | --- | --- | --- |
| C1 | Selector names | `GregorianMonth may name`, `printString`, `FixedOffsetRuleset for:`, `april first , 2025`, `DayOfWeek monday`. | `fullName()` (enums reserve `name()`), `toString()`, `FixedOffsetRuleset.of(...)` (`for` is a keyword), `april.first().of(2025)`, `DayOfWeek.MONDAY`. | Java naming rules. | C2 | Missing selectors | `april thirtyFirst` raises `MessageNotUnderstood`. | `april.thirtyFirst()` throws `UnsupportedOperationException`. | Smalltalk only defines the ordinal selectors that fit each month; Java interfaces must declare them all. | `GregorianDateTest.testInstanceCreationFor30DaysMonth` |
| C3 | Exception classes | `InstanceCreationFailed`, `ArithmeticError`. | `InstanceCreationFailedException`, `ArithmeticException`, with the same message texts. | Java exception idiom. | `FixedOffsetRulesetTest.testCantCreateOutOfRange`, `GregorianDateTest.testInstanceCreationForFebruaryOnCommonYear` |
| C4 | Day-of-month interning | `CalendarDayOfMonth` instances are interned, so equal days are identical. | `CalendarDayOfMonth` is a record compared by value. | Equality is what callers use; identity is not observable through the public API. | `DifferencesTest.daysOfMonthAreValuesNotInternedInstances` |
| C5 | Abstract classes | `CalendarDate`, `CalendarYear`, `CalendarMonthOfYear`, `CalendarDateTime`, `CalendarMagnitude` are abstract superclasses. | Generic interfaces with default methods; Gregorian types are final classes. | Enums (`GregorianMonth`, `DayOfWeek`) cannot extend classes, and `sealed` across packages and modules (Hebrew, Islamic, timezones) would need JPMS. | `DifferencesTest.abstractSmalltalkClassesAreInterfacesAndGregorianTypesAreFinal` |
| C6 | Instant precision | `Instant` holds any quantity of microseconds. | Same (exact `TimeQuantity`); `toJavaInstant()`, `toLocalTime()` and `toOffsetDateTime()` truncate below the microsecond or second that `java.time` can hold. | `java.time` interop only; core arithmetic stays exact. | `DifferencesTest.instantsStayExactAndTruncateOnlyAtJavaTimeInterop`, `TimeOffsetPropertiesTest.fixedOffsetDateTimesAgreeWithOffsetDateTime` |
| C7 | Float offsets in messages | `FixedOffsetRuleset for: -16.1 * hour` fails with `-16.1 h is out of range...`. | The message reads `(-161/10) h is out of range...`. | Consequence of M1/M2: decimals are exact fractions. | `FixedOffsetRulesetTest.testCantCreateOutOfRange` |
| C8 | Localization hook | `NaturalLanguageTranslator` and `CurrentLocale` dynamic variables. | `org.chalten.localization.Translations` reads the shared `locales/` catalogs; `Translations.during(translator, action)` and `duringLanguage(language, action)` scope a translator. Locale-aware formatting is U4. | Thread-scoped equivalent of the Smalltalk dynamic variables. | `GregorianMonthTest.testNamesAreLocalized`, `DayOfWeekTest.testNamesAreLocalized` |

## Preserved Smalltalk limitations

These are not differences: the Java port reproduces the Smalltalk results on purpose, and the properties restrict their generators to the range where the Smalltalk arithmetic is correct (`ChaltenArbitraries.FIRST_JULIAN_DAY_YEAR` and `FIRST_DAY_OF_WEEK_YEAR`). They were found by the U5 properties and derived from the Smalltalk source, which uses the same operations (`truncated`, `rounded`, `//`, `\\`).

| # | Area | Smalltalk | Java | Reason | Test |
| --- | --- | --- | --- | --- | --- |
| S1 | Julian day numbers before -4713-11-24 | `GregorianDateTime>>julianDayNumber` truncates `36525 / 100 * (yearNumber + 4716)` toward zero, so `GregorianDate>>dayOfWeek` is one day late before March 1, -4716 (`January 1, -4716` answers Sunday; it is a Saturday). `EdwardGrahamRichardsAlgorithm>>normalize:` uses `Number>>rounded` (half away from zero), so a date-time whose Julian day number is negative and ends in `1/2` (midnight before -4713-11-24T12:00) converts to the day before: `January 1, -4713` at midnight in UTC comes back as `December 31, -4714`. | Identical results. | Behaviour-preserving port; neither date range is reachable from policy dates. Fixing it would change results that the Smalltalk implementation answers. | `JulianDayNumberLimitsTest` |
